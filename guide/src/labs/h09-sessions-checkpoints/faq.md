# FAQ

## 세션 재개와 파일 되돌리기

세션 snapshot은 model에게 다시 보낼 대화와 관련 상태를 저장한다. 프로젝트 파일의 이전 버전을 보관하지는 않는다. 종료한 사이 파일을 바꿨다면 재개한 hel은 현재 파일을 읽는다. 파일을 되돌리려면 Git 같은 별도 버전 관리 수단이 필요하다.

cursor도 이전 파일 내용을 보관한 사본이 아니다. 읽던 파일의 경로·위치·식별 정보를 가리킨다. 파일이 달라졌다면 기존 cursor를 거절하고 새로 읽게 한다. 세션 소유 spill은 원문 파일을 보관하므로 같은 파일이 남아 있는 동안 이어 읽을 수 있다.

## 답변이 끝나기 전에 중단된 경우

마지막 저장에 성공한 완료 지점까지 재개한다. 처리 중인 tool 호출마다 snapshot을 쓰거나, 외부 변경이 이미 적용됐는지를 추적하지 않는다. 강제 종료 뒤 같은 지시를 다시 보내면 이미 실행한 변경을 반복할 수 있다.

중간 복구가 필요해지면 호출 식별자, 실행 전후 기록, 부작용 확인과 재실행 정책을 함께 설계해야 한다. 이번 snapshot만으로 정확히 한 번 실행하거나 파일을 되돌리는 성질이 생기지는 않는다.

## 세션 폴더를 다른 프로젝트로 옮긴 경우

현재 구현은 snapshot에 저장한 작업 경로와 실행 중인 작업 경로가 다르면 재개를 거절한다. 대화 속 경로·cursor·spill 참조를 함께 옮기는 기능은 없다. 프로젝트 이동이나 세션 분기가 필요해지면 그 참조를 어떻게 재해석할지 별도로 정해야 한다.

## 같은 문맥과 같은 답변

설정과 파일이 그대로이고 필요한 상태를 복원하면 이전 문맥으로 요청할 수 있다. 그래서 대화 내용의 저장·복원은 고정 응답으로 검사하고, 실제 model에는 이전 식별자를 활용해 답하는지를 따로 확인했다.
