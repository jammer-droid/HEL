# FAQ

## 여러 자식을 동시에 실행하면

이번 Lab의 부모는 자식 하나를 실행하고 끝날 때까지 기다린다. 서로 의존하지 않는 작업을 여러 자식에게 나눠 동시에 실행하면 전체 작업 시간이 줄어들 수 있다. 대신 같은 파일을 고치는 충돌과 결과를 합치는 비용이 생긴다. 순차 위임에서 확인한 문맥 전달 방식과 자원 사용을 바탕으로 H12 Parallelism에서 이어서 살펴본다.

## 사용자가 자식 agent에게 직접 지시하려면

이번 구조에서 자식은 부모의 tool 호출로만 만들어지고, 사용자는 부모와만 대화한다. Claude Code와 Codex는 끝난 자식에게 메시지를 다시 보내 이어서 작업하게 할 수 있다. 사용자가 자식을 고르거나 자식에게 직접 지시하려면 자식의 대화 기록을 저장하고 다시 불러오는 H9 세션 기능과 함께 다뤄야 한다.

## 부모가 넘길 정보가 많으면

이번 작업에서 부모가 자식에게 넘길 정보는 port 값 하나였고, 부모는 세 방식 모두 작업 지시에 값을 직접 적었다. 넘길 정보가 여러 파일의 내용이나 긴 조사 결과라면, 위임 지시만 받는 방식은 부모가 지시에 담지 못한 정보를 자식이 다시 찾아야 한다. 전체 복사는 정보를 빠뜨리지 않지만 자식이 부모만큼 큰 문맥에서 시작한다. 넘길 정보의 양에 따른 세 방식의 성공률과 비용은 H13 Harness Evaluation에서 비교할 수 있다.

## 자식이 돌려주는 결과의 형식

`hel`은 자식의 최종 답을 그대로 부모의 tool 결과로 넣는다. 자식에 따라 바뀐 줄만 돌려주기도 하고, 파일 전체나 수정 과정을 길게 돌려주기도 했다. Claude Code와 Codex도 자식의 최종 메시지를 돌려준다. 여러 자식의 결과를 모아 합치는 H12 Parallelism에서는 결과 형식을 정하는 방법을 함께 살펴본다.

## 자식에게 전달되는 확장과 권한

H10에서 넘어온 질문이다. `hel`의 자식은 부모와 같은 사용 가능한 tool 목록, 접근 레벨, 권한 판정, hook을 그대로 쓴다. skill 상태는 부모 것을 복제해 쓰고, 자식이 끝나면 부모 상태로 되돌린다. Claude Code는 subagent 정의마다 tool, 권한 모드, hook, skill, MCP 서버를 따로 지정할 수 있고, Codex는 역할 설정으로 자식의 설정을 바꾼다. 자식마다 다른 범위를 주는 구조는 여러 자식을 함께 실행하는 H12에서 작업 공간을 나누는 문제와 이어진다.

## cache hit가 64 token 단위로 끊기는 점

이번 측정의 cache hit token은 모두 64의 배수였다. DeepSeek 문서는 저장 단위가 입력과 출력이 끝나는 위치에 생긴다고만 설명하고, 64 token 묶음은 측정값에서 추론한 것이다. 같은 앞부분이라도 마지막 64 token 묶음을 채우지 못한 부분은 hit되지 않으므로, 요청마다 최대 63 token을 다시 계산한다. 다른 model이나 provider의 cache 단위와 비용은 H13에서 구성별 비용을 비교할 때 함께 확인한다.
