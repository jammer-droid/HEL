# FAQ

## 인스턴스별 디렉터리와 세션 저장의 차이

H8의 인스턴스별 디렉터리는 동시에 동작하는 hel 인스턴스의 임시 데이터 접근을 나누는 단위다. hel을 종료한 뒤 대화를 이어 가는 기능까지 포함하지 않는다. 대화 기록과 실행 상태를 저장하고 복원하는 방법은 H9 Sessions & Checkpoints에서 다룬다. 임시 데이터의 보관·정리 규칙과 재개에 필요한 데이터의 수명은 그때 연결해서 살펴볼 수 있다.

## 같은 프로젝트에서 두 hel을 실행하면 파일도 분리되는가

각 hel 인스턴스의 tmp와 spill을 분리해도 같은 프로젝트 경로를 허용하면 프로젝트 파일은 공유된다. 동시에 같은 소스를 고치는 충돌을 피하려면 작업 디렉터리 자체를 나눠야 한다. 병렬 작업의 배정과 결과 통합은 H12 Parallelism에서 다룬다.

## 실행 중에 sandbox 권한을 넓힐 수 있는가

hel이 실행 중일 때 추가 경로와 읽기·쓰기 권한을 사용자에게 승인받는 기능은 만들 수 있다. H8에서 사용하는 sandbox-exec 방식으로 이를 확장한다면, hel 본체가 승인을 받고 확장된 정책을 적용한 새 프로세스에서 명령을 실행하면 된다.

OS는 파일 접근을 자동으로 멈춰 승인창을 띄워 주지 않는다. 승인 요청과 재실행은 harness가 처리해야 한다. 필요한 경로를 미리 알면 실행 전에 승인받을 수 있고, 접근 실패 후에 요청한다면 명령이 이미 일부 작업을 수행했을 가능성을 고려해야 한다. 재실행의 경우 파일 변경 등이 중복될 수 있으므로 실패한 위치부터 그대로 이어진다고 가정해서는 안 된다.

H7의 tool 실행 승인과도 구분한다. 명령 실행에 동의해도 sandbox가 허용하는 파일 범위가 자동으로 넓어지지는 않는다. 권한 상향을 추가할 때는 승인한 명령 한 번에만 적용할지, 이후 호출에도 유지할지 정해야 한다.

H8에서는 hel 인스턴스를 시작할 때 정한 경로 정책을 고정한다. 실행 중 권한 상향은 후속 확장 과제로 남기고, 허용 범위 밖 접근은 오류로 반환한다.
